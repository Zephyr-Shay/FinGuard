# FinGuard V1.0

智御未来团队的模拟银行 AI 智能体。界面、健康接口、代码包和提交材料统一采用V1.0；延续开发阶段已完成的资金安排、账单分析、安全执行与存储实现。

## 快速体验

使用Node.js 24或更高版本，在源码目录执行：
```
node tools/provision-demo.mjs --create
node server.mjs
```
访问 http://127.0.0.1:4317 ，测试账号 **tester**，登录密码 **tester**。登录页可点“填入测试账号”，仍需手动确认登录。全部资金和交易均为模拟；该共享账号不要录入个人资料。

共享测试账号只能由上述离线工具显式创建，不开放普通账户注册或在线重置。独立体验开设须显式启用，见下节。账号已存在且未被标记为本工具创建，或密码已修改时，工具停止，不覆盖原账号。普通账号通过node provision.mjs创建随机初始口令，密码规则保持原样。登录密码不代替支付密码和TOTP；敏感操作仍按服务端要求验证。

## 验证和模型

执行 node --test --test-concurrency=1 tests/*.test.mjs 。本版355项自动测试通过、58项浏览器检查通过。界面检查采用隔离合成账号与固定模型回复，不代表真实模型准确率。开发阶段26项历史模型固定任务单列在evidence/history，保留原始版本文件，不冒充本版重测。

未配置外部模型时标明本地规则模式。配置方法和上线迁移见DEPLOYMENT.txt；密钥仅在服务端，用户同意后才发送必要资料。每日用户及全站请求与Token配额持久化。源码不含服务器登录凭据、生产数据库或部署密钥；tester/tester是明确公开的演示凭据例外。

## 数据和运维

认证、业务状态、订单、回执和HMAC审计共用SQLite库。旧state.json首次导入后保留但不回写。迁移后不得用旧JSON覆盖，也不能自动回退到开发期JSON账务版本。备份整个数据目录及密钥。HMAC链仍需独立只增审计存储，供应商数据治理也需运营方核验；不宣称真实银行核心账务能力。

人工体验见TEST-CASES.txt。公网部署结果以本包部署核验记录为准。

## 转账意图与金额核对

模型提出的普通及多步转账候选须与用户当前输入或尚待补充会话的明确金额核对。服务端联系人姓名与别名用于解析收款人，逐笔比较收款人ID、金额和笔数；正确重排允许，对调、复用、漏项或加项继续追问，不签发确认凭证。追加或减少金额须确认最终总额，不自动累计历史金额。复杂表达可能需要用户逐笔重述，日期业务合法性校验不等于完整意图证明。

普通转账在接口和Engine入口核对；多步计划在接口核对后交给draftPlan执行独立业务校验。不能把相同函数重复调用视为两套独立算法。既有确认、身份验证、限额、预算、执行前复核与幂等机制保持独立。

本轮演示重置修订新增7项自动用例、9项界面流程检查，总计355项自动测试和58项隔离界面检查通过。测试均采用合成数据与固定候选。真实模型26任务仅为开发期历史结果。本版没有重跑真实模型评测。

跨场景联动覆盖资金侧安排，现有入口为“统一资金安排”。Web、联系人转账、月度年度报告等已实现；手机号识别、卡申请、商户预订及IM连接未实现。应用价值及银行接入仍待验证。

## 独立体验账户

优先在登录页选择“创建独立体验账户”，保存随机登录资料后进入。每位访问者单独保存余额、账单、支付密码与手机验证器；新账户没有预设支付密码或 TOTP，需在“卡片 → 安全设置”通过本人登录密码设置。共享 tester/tester 只作浏览入口，不公布其现有支付配置。部署升级不会清空已有安全设置；用户主动重置演示时，按下述身份核验流程处理。所有资金均为模拟。

本地显式启用：PowerShell 执行 `$env:FINGUARD_REVIEW_DEMO='1'` 后运行 `node server.mjs`；Linux 执行 `FINGUARD_REVIEW_DEMO=1 node server.mjs`。随包 compose.yaml 已为比赛模拟部署显式启用。关闭该变量即停止新账户开设，已有账户与业务记录保留。

`POST /api/auth/demo-space` 仅接收由浏览器生成的体验账号与随机密码；同一资料重试只恢复同一账户。密码摘要存储、正常会话、同源校验及后续支付/TOTP 规则仍有效。默认每来源每日20次、全站每日80次、总计500个体验账户，最多并行2个创建请求；来源计数保存摘要，按北京时间午夜重置。可信代理配置影响来源划分，公网未单独证实真实来源分离，不把来源额度视为唯一防滥用措施。

完整姓名先于别名匹配。“陈晨”唯一时直接形成待确认候选；“小陈”仍保留两位候选并追问。确定性纠正仅覆盖完整、即时的简单转账子句，条件、日期、追问引用等仍走原规划与核验路径。不把追问纠正视为批准交易。

## TLS 续期维护

公网 IP 网关原有 finguard-ip-renew.timer 每6小时调度 Certbot。2026-11-02 完成一次 staging dry-run；原定时器保留，并在续期及 Nginx reload 后核验443/8443证书与磁盘叶证书一致、主机名和信任链有效、剩余有效期不少于48小时。脚本见 deploy/check-tls.py 与 deploy/renew-gateway.sh。失败通过 systemd 结果和日志显现；尚无独立外部告警，不承诺评审期绝不会中断。脚本不包含证书或私钥。

## 主动重置演示与重新设置验证

从任意页面的个人菜单选择「重置演示数据」，核对当前登录密码；已绑定验证器时，还须输入未使用的当前手机动态验证码。确认后，在同一 SQLite 事务中恢复当前账户的样例、清除支付密码和已绑定及待确认的验证器、关闭小额免密并清除可信收款人，同时撤销原会话。浏览器自动换用新会话，无须重复登录；弹窗可直接进入账户安全重新设置。其他账户不受影响。

登录密码、历史归档与审计、模型使用配额及累计安全额度不因演示重置清零。旧密码和验证码不能继续付款。没有原验证器时，不能靠重置解除二次验证，应创建独立体验账户或联系管理员核验。升级发布本身不触发任何账户重置。
